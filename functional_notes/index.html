Functional Notes¶

Message Types:

system — generated by core transactional systems (address changed, account opened, statements ready).

bulk — generated for events affecting multiple users (dividend applied, corporate events).

Critical Fields:

messageId, userId, type, status, timestampUtc

category — domain grouping (e.g., Profile, Dividends, CorporateAction)

actions — UI actions (view, download, acknowledge)

pushNotification — controls notification dispatch

Validation Rules:

  • User must be authenticated

  • userId in JWT must match user in payload (ownership check)

  • messageId must belong to user

  • title and content are mandatory

  • type must be system or bulk

  • timestampUtc must be valid ISO 8601

  • category must be valid domain enum

  • If pushNotification = true, verify user notification preferences

  • If message action is acknowledge, enforce that message cannot be auto-dismissed

  • Read state transitions must be valid (cannot un-read)

Transformations:

  • Merge system messages + bulk messages

  • Sort descending by timestampUtc

  • Map backend entity to MessageSummaryDTO and MessageDetailDTO

  • Localize timestamps using user locale/timezone

  • Truncate content to form summary text

  • Convert internal backend enums/flags into UI-friendly values

  • Strip internal metadata not required by UI

  • Remove duplicate messages where system + bulk overlap

  • If backend message actions reference internal codes, normalize them to canonical UI actions

Unread Count Handling:

  • unreadCount is persisted in message store

  • unreadCount is exposed via /messages/unread

  • unreadCount decrements when marking message as read

  • multi-device sync is mandatory — next login always reflects persisted read state

  • local cache is permitted for UI performance but must refresh on app resume

  • optimistic updates allowed but must reconcile on re-fetch

Push Notifications:

  • Triggered only when: message is unread and pushNotification = true and user preference allows notifications

  • After message is marked read: stop further notifications , remove badge count on mobile device

  • Device token lookup performed during notification dispatch

Pagination & Filtering:

  • page & pageSize supported to avoid large payloads

  • Default page size: 20

  • Maximum allowed page size: 50

  • Optional filtering:

    • by message type (bulk | system)

  • by category (corporate action, account change, security updates)

  • by unread status

  • Paging must be stable: identical sort order guarantees correct cursor movement

Error Handling:

  • 401 Unauthorized — invalid JWT or missing internal auth

  • 404 Message Not Found — invalid id or not owned by user

  • 500 Internal Server Error — downstream bulk/system failures

  • Partial failures:

  • If one upstream API fails, still return messages from others and mark partialResult flag

  • Developer must log root cause + request ID

Edge Cases:

  • Offline mobile: cached messages allowed & read operations queued and reconciled when online

  • Partial fetch tolerance: If bulk API fails, return system messages only + flag degradedMode

  • Duplicate prevention: Deduplicate by messageId

  • Large inbox: enforce paging/windowing strategy and avoid full payload returns
